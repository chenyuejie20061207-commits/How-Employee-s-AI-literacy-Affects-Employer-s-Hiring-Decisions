# 爬取与脱敏说明

## 1. 交付范围

本目录交付任务一的原始素材，而不是最终投放用的虚拟简历：

- `原始素材_岗位与简历结构.csv`：正式数据表，UTF-8 with BOM、标准 CSV 引号、CRLF 行尾，固定 23 字段。
- `虚拟数据库字段字典.md`：字段、枚举、缺失值、行粒度和哈希口径。
- `爬取与脱敏说明.md`：本文件，说明来源、准入、采集、清洗、脱敏和去重。
- `数据质量报告.md`：正式数据的数量、分层、完整性、来源集中度、复核状态和限制。
- `来源合规登记.csv`：逐来源记录访问方式、robots/条款核查、准入结论和限制。

当前正式表为 **400 条岗位 JD + 80 条简历结构素材**，共 480 行。一行代表一个独立岗位文档，或一条从公开写作指南抽象出的简历栏目结构；没有把一个 JD 拆成多行凑数。简历结构素材不包含任何真实个人简历原文。

## 2. 样本设计

### 2.1 岗位 JD

采用“岗位类型 × 城市”的 16 层设计：

- 岗位类型：`IT/技术类`、`管理类`、`非常规认知型`、`常规型`，互斥分类，优先级依次为 IT/技术类 → 管理类 → 非常规认知型 → 常规型。
- 城市：北京、上海、广州、深圳。
- 目标：每层 25 条，合计 400 条。

岗位名称保留原值，分类依据写入 `分类理由`。企业名称、行业、性质、规模只记录公开值；未公开统一写“未披露”，不按企业名称猜测。

### 2.2 简历结构素材

采用“岗位类型 × 简历栏目”的 4×4 矩阵：

- 岗位类型同上四类；
- 栏目：教育结构、实习结构、项目结构、技能结构；
- 每格 5 条，合计 80 条。

每条只描述栏目顺序、子字段、取舍规则、量化方式与岗位适配理由。例如“教育结构按学历、专业、课程模块排序，并用排名区间占位”，不复制指南中的示例简历，也不保留姓名、学校班级、企业项目或联系方式。

## 3. 来源准入

### 3.1 校招宝开放 API

正式 JD 的主要来源为校招宝公开、免 Key、匿名的开放 API：

- 接口：`https://xiaozhaobao.com.cn/api/open/v1/jobs` 及 `/jobs/:id`。
- `robots.txt` 明确 `Allow: /api/open/v1/`，同时对 `/api/` 其余路径作限制；本项目只访问显式开放的 `/api/open/v1/`。
- 接口元数据允许检索、问答、推荐、展示等用途，要求保留“数据来源：校招宝”和含 `ref` 参数的站内链接，禁止整库转载、构建竞争性岗位数据库或批量转售。
- 本项目只做 16 个分层的限量研究抽样，保存检索关键词、原始岗位 ID、采集时间和归因链接；不抓取投递入口，不绕过登录或访问控制。
- 单线程请求，程序自限两次请求间隔不少于 6 秒；缓存响应；遇到 401/403 或访问控制立即停止，429 按 `Retry-After` 限量重试。

### 3.2 公开快照交叉核验

校招宝开放 API 的详情对象不直接暴露外部原始来源 URL。为满足“来源可追溯”，项目使用校招宝公开 GitHub 仓库 `kknee-dev/recruit-hub` 的三期公开 CSV 快照，按“企业 + 岗位名称 + 城市”匹配原始发布域名和 URL：

- `jobs-2026-09-03.csv`，SHA-256 `60e97755c4faf8cd2a2290364527654e7b421db31ae3da783614de1dbe90accb`；
- `jobs-2026-10-01.csv`，SHA-256 `3b587b8cb0d5f60e845157e4ce9bd3a3a59a9ab71e844691781243e3907d2825`；
- `jobs-2026-11-01.csv`，SHA-256 `00c6aa8fff93e2acf237bc3f606299875003bbd6b6ae3f448895d328c4eb392c`。

匹配时统一 Unicode NFKC、大小写和空白，并去除岗位编号 `(Jxxxxx)`、年份批次、校招/秋招/春招等不改变岗位实质的后缀；企业名去除“股份有限公司/有限公司/集团”等组织形式后匹配。只有城市一致、岗位实质一致且能取得非受限 `source_url` 的记录才进入正式表。匹配不到原始链接的 API 记录不进入最终数据，不猜测链接。

正式表的 `来源URL` 为匹配到的原始公开招聘页；`其他来源URL` 保留校招宝含 `ref` 的归因链接，`来源平台` 同时注明“校招宝开放API整理”，以满足开放接口的署名要求。

### 3.3 企业维度字段

缺失的行业优先按同一企业其他公开快照记录回填；仍缺失时，查询校招宝公开企业档案 `/api/open/v1/companies`，只有企业名称完全匹配且行业字段明确时才采纳。企业性质按公开值统一明显异名，不根据企业名称推断。企业规模在公开接口和快照中均未提供时统一保留“未披露”，不做估算。

### 3.4 简历结构指南

80 条结构素材依据公开高校就业指导页、简历写作指南和公开 PDF 的栏目框架抽象，不复制范文。具体来源平台、URL 和结论见 `来源合规登记.csv`。

### 3.5 明确排除的来源

- `ncss.cn` 及其全部子域：用户协议限制未经书面许可下载、复制和再使用，项目在爬虫和终验两层技术拦截。
- `gaoxiaojob.com`：robots 为 `Disallow: /`，不进入最终素材。
- `yzu.91job.org.cn`：robots 为 `Disallow: /`，不进入最终素材。
- 2026-11-21 补采预检中，`jobs.bjbys.net.cn`、`job.tiangong.edu.cn`、`jyzd.ucass.edu.cn`、`job.xju.edu.cn`、`career.tyut.edu.cn` 的 robots.txt 返回 404；`job.njtu.edu.cn` 的 TLS 证书主机名不匹配。按“robots 缺失不视为授权”的规则，**从这些站点直接采集的候选全部隔离**。
- 说明：正式表中有 2 条北京岗位的来源链接指向 `jobs.bjbys.net.cn`，但其 JD 正文由校招宝开放 API 合法返回，项目没有抓取该站页面；该链接仅作为公开出处标注，`来源平台` 已注明“校招宝开放API整理”。这不是把 robots 缺失解释为采集授权。

## 4. 采集程序与断点

### 4.1 岗位发现

1. 以四类岗位的操作化关键词检索四城市公开岗位；
2. 每个关键词读取第 1–3 页，按 `sort=quality` 排序；
3. 只保留 `jd_available=true`、城市匹配、标题符合分类优先级的岗位；
4. 通过公开快照匹配原始来源，排除受限域名和非法 URL；
5. 按来源域名和企业做多样性排序，再读取详情；详情正文必须 100–6000 字并含职责/要求语义。

### 4.2 断点与重复控制

- `work/jd_pool.json` 保存中间池；
- 分层是否完成由“实际有效条数达到目标”决定，不由是否存在部分记录决定；
- 续采只补缺口，并按全池 `原始岗位ID` 和文本哈希排除已有记录，避免重复追加；
- 输出采用临时文件替换，降低中断造成半截 JSON 的风险。

### 4.3 可复现脚本

- `scripts/collect_xzb.py`：开放 API 的限量抽样与断点续采；
- `scripts/clean.py`：清洗、精确去重和近似重复候选；
- `scripts/deidentify.py`：PII 扫描与掩码；
- `scripts/validate.py`：字段、枚举、URL、哈希、PII、分层和集中度验收；
- `scripts/export.py`：固定 23 字段导出；
- `tests/test_pipeline.py`：离线测试，不访问招聘网站。

开放 API 采集脚本默认读取 `work/` 下的三期快照和缓存。快照属于公开辅助溯源材料，未提交到仓库；可按上列文件名和 SHA-256 从公开仓库取得。运行命令：

```bash
python scripts/collect_xzb.py
python -m pytest tests/test_pipeline.py -q
```

## 5. 清洗规则

1. Unicode NFKC 规范化，统一全半角；
2. CRLF/CR 统一为 LF，移除控制字符，合并多余空格和空行；
3. 保留正文语义和内嵌换行，不删除职责、要求等结构；
4. 去除外部投递链接或替换为占位符；
5. 上游返回的少量 Unicode 替换字符统一记为 `□`，不猜测补字，并在质量报告披露；
6. 清洗后重新计算文本哈希，CSV 读写使用标准双引号转义。

## 6. 脱敏与虚构化

- 不采集真实个人简历，不保存简历模板或指南中的示例个人资料。
- 对 JD 正文中的手机号、固定电话、邮箱、身份证号、QQ、微信、联系人姓名执行掩码；举报只记录类型和位置，不记录敏感原值。
- 结构素材只保留栏目、顺序、泛化类别和量化占位，删除具体姓名、学校班级、企业项目、详细地址和社交账号。
- 正式表通过 `deidentify.scan_pii()` 复扫；PII 残留计入验收错误，不能带病交付。

## 7. 去重

1. 对清洗、脱敏后的完整正文计算 SHA-256，删除精确重复；
2. 对 JD 计算 RapidFuzz 相似度，达到 92 的记录标为近似重复候选；
3. 近似重复不是“算法一判就删”：逐组核对岗位名称、企业、城市和正文差异。不同专业方向、不同企业或不同城市的岗位即使共用招聘模板，也作为独立发布保留；只有同城市、同企业、同岗位名称的转载才合并；
4. 同一岗位被多个城市检索命中时保留质量最高的一条，并记录被移除的城市；
5. 正式表交付时 `重复组ID` 必须为空，未处理的近似重复组不能留在主表；
6. 处置数量、候选对和保留/合并明细写入 `质量核查记录.json`。

## 8. 质量门槛

- 固定 23 字段、枚举合法、ID 全表唯一、哈希与正文一致；
- JD 100–6000 字，结构素材 20–600 字；
- 来源 URL 有效且不属于排除域名；
- 无 PII 残留；
- 16 个 JD 分层和 16 个结构矩阵单元的计数真实报告，缺口不伪造；
- 来源域名、企业集中度和分层配额写入质量报告；
- `人工复核状态=自动校验通过（待人工复核）` 明确表示自动检查和独立内容复核完成，但不冒充小组第二人签字。

## 9. 使用边界

本数据仅用于劳动经济学课程的非商业研究设计，不是招聘岗位镜像库，不提供投递入口，不用于转售、批量转载或构建竞争性岗位数据库。岗位发布时间、截止时间和来源页面可能变化，正式分析前应按研究设计再次核对抽样时间窗口。
