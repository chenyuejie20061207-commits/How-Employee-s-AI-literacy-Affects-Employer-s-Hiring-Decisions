# 虚拟数据库字段字典

## 1. 数据表定位与行粒度

数据文件为 `原始素材_岗位与简历结构.csv`，采用 UTF-8 with BOM、标准 CSV 双引号转义和 CRLF 行尾。

- **岗位 JD**：一行代表一个独立岗位文档，`字段类型=岗位JD`。正文保留公开岗位职责与任职要求，不把一个 JD 拆成多行重复计数。
- **简历结构素材**：一行代表一条从公开简历写作指南抽象出的栏目结构，`字段类型`为教育、实习、项目或技能结构。只描述字段、顺序、组织方式和量化方式，不包含个人简历原文。
- **虚构简历条目**：一行代表一条可独立拼装的虚构模块经历，`字段类型`为教育经历、实习经历、项目经历或技能条目。内容为虚构化改写的具体文本（虚构机构、类别泛称院校、通用量化），可按模块组合成完整虚构简历；不对应任何真实求职者。
- `素材ID` 在全表唯一。任务二可据此连接识别与分类结果，不应使用 CSV 行号作为稳定键。

## 2. 枚举与缺失值口径

### 来源类型

| 值 | 含义 |
|---|---|
| 公开招聘平台 | 公共招聘、高校就业或企业招聘公开页面；本轮 JD 正文经校招宝开放 API 整理时，会在来源平台和另一来源链接中同时说明 |
| 招聘信息聚合站 | 仅能以聚合站为可追溯来源的公开招聘信息；本轮最终保留记录须另有非受限原始链接 |
| 公开简历模板 | 公开简历写作指南、模板或高校就业指导；作结构抽象与措辞模式参考（虚构条目据此虚构化改写，不复制范文原文） |

### 岗位类型

采用以下优先级实现互斥采样，原始岗位名称不覆盖，后续可复核重分类：

1. **IT/技术类**：软件、算法、研发、测试、运维、网络、硬件、工程技术等。
2. **管理类**：人力资源、行政、项目、供应链、财务、审计、运营或生产管理等；若已明确属于 IT/技术类，不重复归入管理类。
3. **非常规认知型**：不属于前两类，且以分析、研究、设计、咨询、创意、法律、市场或决策任务为主。
4. **常规型**：客服、销售事务、文员、助理、出纳、柜员、操作、检验、仓储、跟单等相对例行任务。

### 字段类型

`岗位JD`、`教育结构`、`实习结构`、`项目结构`、`技能结构`、`教育经历条目`、`实习经历条目`、`项目经历条目`、`技能条目`。

前五类为原始素材（JD 与规则层），后四类为虚构简历条目（内容层）；两层并存、互相呼应：每个“岗位类型×模块”格既有 5 条结构规则，也有 5 条虚构内容条目。

### 行业与企业性质口径

- 行业优先保留公开值，并将明显异名统一为：`信息技术/互联网`、`电子信息/通信`、`金融业`、`制造业`、`科学研究和技术服务`、`能源/化工`、`消费品/日化`、`批发零售/电商`、`房地产/建筑`、`文化/传媒`、`商务/生活服务`、`医疗健康/环保`、`医疗健康/生物医药`、`交通/物流/仓储`、`航空航天/国防`、`汽车/新能源`、`公共管理/社会组织`、`综合/多行业`。
- 同一企业披露多个行业时保留为 `综合/多行业`；把岗位职能误填为行业的原值（如“策略算法”“人力/行政/财务”）不保留为行业。
- 企业性质统一为：`民营企业`、`国有企业`、`外资企业`、`外资/合资企业`、`事业单位`、`科研事业单位`、`机关/事业单位`、`其他`。

### 缺失与未披露

- 企业未公开的行业、性质或规模填 `未披露`，不根据企业名称猜测。补充行业时只接受同一企业其他公开记录或校招宝公开企业档案中的明确值。
- 简历结构素材的城市填 `不适用`，行业填 `未披露`，企业名称填 `不适用`，企业性质和规模填 `未披露`。
- 虚构简历条目的城市填 `不适用`。教育/技能条目企业名称填 `不适用`、行业与性质规模填 `未披露`；实习/项目条目企业名称填 `虚构机构名登记表.csv` 中的虚构专名，行业/性质/规模取登记属性（枚举内取值）。
- 可选URL没有值时留空；核心溯源字段不得为空。
- `待复核`、`自动校验通过（待人工复核）`、`已通过`、`已驳回`仅表示本项目的数据与语境检查进度；`自动校验通过（待人工复核）`明确说明尚未完成人工签字，不代表小组第二人独立复核已完成。

## 3. 字段定义

| 字段 | 必填 | 定义与规则 |
|---|---|---|
| 素材ID | 是 | 全表唯一稳定ID。JD使用`JD-XZB-{公开岗位ID}`；结构素材使用`RES-{岗位}-{栏目}-{序号}`；虚构条目使用`VRE-{岗位短码}-{栏目短码}-{序号}`（IT/MGT/NRC/REG × EDU/INT/PRJ/SKL） |
| 来源类型 | 是 | 使用上述枚举 |
| 岗位类型 | 是 | 使用上述四类互斥操作标签 |
| 行业 | 是 | 优先保留公开原值并统一明显异名；未知填`未披露` |
| 城市 | 是 | JD限定北京、上海、广州、深圳；多城市岗位按本次检索目标层记录，原始城市信息不用于伪造其他城市样本；结构素材填`不适用` |
| 字段类型 | 是 | 使用上述五类枚举 |
| 文本内容 | 是 | JD为清洗和脱敏后的公开正文；结构素材为不可回溯的结构描述；虚构条目为虚构化改写的模块经历文本。JD长度100–6000字，结构素材20–600字，虚构条目30–400字 |
| 采集时间 | 是 | 带时区ISO 8601时间。API记录采用响应生成时间；人工结构抽象采用实际处理时间 |
| 来源记录ID | 是 | 来源平台内稳定记录标识；结构素材可包含指南与栏目编号 |
| 来源平台 | 是 | 实际公开平台名称；JD经聚合整理时注明“校招宝开放API整理” |
| 来源URL | 是 | JD为已匹配并排除受限域名的原始公开链接；结构素材为公开指南链接 |
| 其他来源URL | 否 | JD保留校招宝站内归因链接，包含其要求的`ref`参数；结构素材可留空 |
| 原始岗位ID | JD必填 | 公开岗位原始ID；结构素材留空 |
| 采集批次 | 是 | 采集或抽象批次，如`xzb-openapi-2026-11-21`、`public-guide-structure-v1` |
| 原始岗位名称 | JD必填 | 公开岗位原名称，不为了分类而改写 |
| 企业名称 | JD必填 | 公开企业或招聘单位名称；结构素材填`不适用` |
| 企业性质 | JD必填 | 来源公开值；未公开填`未披露` |
| 企业规模 | JD必填 | 来源公开的员工规模区间；未公开填`未披露`，不估算 |
| 分类理由 | 是 | 检索词和标题规则命中依据；结构素材说明栏目与岗位适配理由 |
| 文本哈希 | 是 | 对`clean.py`规范化后的完整文本计算SHA-256，用于精确去重和完整性检查 |
| 重复组ID | 交付时为空 | 处理中记录精确/近似重复组；交付前必须解决并清空，不能把未处理候选留在主表 |
| 脱敏状态 | 是 | JD为`已脱敏`；结构素材为`结构抽象v1（不含原文）`；虚构条目为`虚构化改写v1（不含原文）`。三类状态按字段族互斥，不允许跨族混用 |
| 人工复核状态 | 是 | `待复核`、`自动校验通过（待人工复核）`、`已通过`或`已驳回`；自动校验不冒充人工签字，第二人复核状态另见质量报告 |

## 4. 文本规范化与哈希

1. Unicode NFKC规范化。
2. 统一CR/LF换行，移除控制字符，合并空格与制表符，清理行首行尾空白。
3. 保留正文语义和内嵌换行；标准CSV读写负责逗号、双引号与换行转义。
4. 对清洗、脱敏后的最终`文本内容`直接计算SHA-256，不对标点或语义作额外删除。
5. 近似重复仅作为候选，使用相似度92为复核阈值；不能把算法候选自动当作确认重复。

## 5. 隐私与使用边界

- 不收集真实个人简历，不保存简历模板或指南中的个人示例原文。
- JD中的招聘联系人、手机、邮箱、微信、QQ、外部投递链接等被移除或掩码。
- 结构素材只保留栏目、子字段、顺序、泛化类别与量化方法；不包含姓名、学校班级、具体企业项目、详细地址或社交账号。
- 虚构简历条目全部为虚构化改写：机构用`虚构机构名登记表.csv`登记的虚构专名（已做撞名预检），院校只用类别泛称，量化只用通用区间；姓名、联系方式等固定模块信息一律不入库，留待任务三拼装时用虚构测试信息生成。条目不对应任何真实求职者或真实经历。
- 国家大学生就业服务平台及其他明确禁止自动抓取的来源不进入交付数据。
- 本表用于非商业课程研究的素材构建，不是招聘岗位镜像库，不提供投递入口，不用于转售或构建竞争性岗位数据库。
